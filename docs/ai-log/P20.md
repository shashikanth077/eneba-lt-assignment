# P20: Deployment (Docker image, vercel.json, DEPLOY.md)

## Prompt

CONTEXT: Free tier targets: Vercel (frontend), Render Docker web service (PHP backend), a free MySQL-compatible host.
TASK: Write a backend Dockerfile (php-apache or php-fpm with nginx), vercel.json with an /api/* rewrite to the backend, env var tables for each service, a migrate-and-seed start step, Stripe webhook registration steps, and a step-by-step docs/DEPLOY.md. Note the cold-start behaviour of the free tier and add a lightweight health-check/warm-up suggestion.
DONE WHEN: I can follow DEPLOY.md from scratch and the public URL completes a test purchase.

## Response summary

**Delivered.** `backend/Dockerfile` (php:8.3-apache, kept Apache because the repo's `.htaccess` and compose file already use it; production php.ini, opcache, dependencies installed `--no-dev` in a cached layer, document root `public/`, listens on `$PORT` so Render's injected port works), `backend/docker-entrypoint.sh` (start step: `RUN_MIGRATIONS=true` runs `bin/migrate.php` with up to 12 retries 5 s apart for a waking database; `SEED_ON_START=if-empty|always|false`; off by default so local Docker is unchanged), `frontend/vercel.json` (`/api/:path*` rewrite to Render, SPA fallback, immutable asset caching), `docs/DEPLOY.md` (names first, database, Stripe, Render, Vercel, wiring check, webhook registration, test purchase, env tables per service, troubleshooting, cold starts and warm-up, rollbacks).

**Code changes the deployment needed.** `DB_SSL`, `DB_SSL_CA`, `DB_SSL_VERIFY` (managed MySQL hosts require TLS; `Database::tlsOptions`, 3 PHPUnit tests); `bin/seed.php --if-empty`; env examples; CI job *API Docker image* that builds the image and starts it like Render does (PORT 10000, `APP_ENV=production`, migrate + seed, health, products, demo sign-in with a Secure cookie, restart is a no-op).

**Verified here.** The start script against a real MySQL (first start migrates and seeds, second start skips, invalid value exits 1, unreachable database gives up); the API in production mode (https `APP_URL`, secure cookie, placeholder secret refused with 500, foreign origin 403, health, demo login); PHPUnit 360 tests.

**Not verified here, stated plainly.** (1) The Docker image could not be built in the sandbox: the build container cannot reach apt through the agent proxy (plain HTTP refused), and a second attempt hit Docker Hub's anonymous rate limit (429). The new CI job is the check. (2) None of the Render, Vercel, Stripe or database dashboards could be used (no accounts), so "the public URL completes a test purchase" is NOT demonstrated; DEPLOY.md is a procedure, written from the platforms' documented behaviour and my knowledge, and free-plan terms change. (3) Whether Vercel forwards `X-Forwarded-For` as assumed (`TRUSTED_PROXY_HOPS=2`) is unverified; the failure mode is a shared rate-limit bucket, not spoofing. (4) The Vercel rewrite may time out on a request that wakes a sleeping Render instance.

**Decisions.** Apache kept over php-fpm + nginx (one process, existing config). Aiven MySQL assumed as the free database because it is real MySQL 8 (the key allocation needs `SKIP LOCKED`); the doc lists what any host must offer. `vercel.json` needs the Render address written in by hand (no env interpolation in that file). The webhook goes straight to Render. Warm-up is a documented external ping of `/api/health` (UptimeRobot/cron-job.org/GitHub Actions), not code.
