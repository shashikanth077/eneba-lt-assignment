# P10: Frontend app shell

## Prompt

front end : app shell

CONTEXT: theme.ts and DESIGN_TOKENS.md exist; API exists.
TASK: Build the layout: header (logo wordmark, global search with live suggestions, cart icon with count, account menu), category/platform nav bar, footer, routing (/, /store, /search, /product/:slug, /cart, /checkout, /login, /register, /account/orders), Redux store with RTK Query API slice, auth slice, and a ProtectedRoute.
CONSTRAINTS: TypeScript strict, generated or hand-written API types, loading/error/empty states as shared components, mobile-first responsive.
DONE WHEN: Search suggestions appear from any page and protected routes redirect to login then back.

## Response summary

- **Built**: `AppShell` (skip link, header, nav bar, routed content in the 1440 px container, footer); header = wordmark, `SearchBox` (MUI Autocomplete, debounced 250 ms, >= 2 chars, server-ranked suggestions with cover/name/platform/out-of-stock marker, typo-tolerant because the backend is), `CartButton` (badge = sum of quantities, no request when signed out), `AccountMenu` (Sign in/Register, or initial + name with orders/cart/sign out); `CategoryNav` (platforms and genres loaded from `GET /api/filters`, fixed shortcuts for All games/Deals/New releases, still works if the API fails, scrolls sideways on phones); footer with only real links and an honest "student project, Stripe test mode" note.
- **Routing**: `/`, `/store`, `/search`, `/product/:slug`, `/login`, `/register` public; `/cart`, `/checkout`, `/account/orders` behind `ProtectedRoute`; 404 page; per-route lazy chunks, `HydrateFallback`, route error boundary. Home/store/search/product/checkout are placeholders by design; login and register are fully working (needed for the redirect round trip), the cart shows real data and orders list real data through the shared states.
- **Data layer**: hand-written API types (`src/api/types.ts`), error helpers (`errors.ts`), one RTK Query API (`app/api.ts`, same-origin, cookies, CSRF header, 401 -> `sessionExpired`), endpoints per feature, `makeStore()` factory, auth slice (`unknown | authenticated | anonymous | error`, plus `signingOut`), a listener that clears the API cache when a session ends. Shared `LoadingState`, `ErrorState`, `EmptyState` and `QueryBoundary`.
- **Done-when, verified in a real browser against the real API and database** (`frontend/e2e/shell.e2e.cjs`, 36 checks): suggestions appear on `/`, `/store`, `/product/x`, `/login`, `/register` and an unknown route (also for the typo "stormhavn"); `/account/orders` redirects to `/login?next=%2Faccount%2Forders`, registering returns to it, a refresh stays, sign out goes home, a wrong password shows the server message and keeps the target, logging in returns to `/cart`, `?next=//evil.example` is ignored; no horizontal overflow at 375 px on 5 routes, suggestions fit the phone screen; no console errors. Screenshots reviewed (desktop and mobile).
- **Tests**: 69 Vitest + Testing Library tests (3 consecutive clean runs): redirect safety (open-redirect cases), error helpers, auth slice (including outage != signed out, cache cleared on logout, expiry resets once), 14 protected-route round-trip tests on the real routes/store/components with an in-memory fake API, 14 search-box tests (debounce, min length, keyboard, encoding, error/empty states, duplicate titles), header/nav/cart-badge tests, state-component tests. Mutation checks, each applied, verified and caught: guard removed, `?next` dropped, open redirect allowed, outage treated as signed out, cache reset on every expiry, sign-out flag removed, route forgetting the sign-out, no debounce, 0-char suggestions, label keys, signed-out cart fetch, Enter not searching.
- **Real bugs found by running it in a browser or by the tests (mine, fixed)**: (1) sign-out from a protected page ended on `/login` because the logout finished before the router/React caught up; `await navigate` was not enough and neither was `flushSync`, so the fix is deterministic state (`signingOut` + the protected route remembering it saw a sign-out); (2) React duplicate-key warnings in the suggestion list (the same title exists on several platforms): key by slug; (3) the sixth suggestion was cut off on desktop: list height raised; (4) a mutation run hung: a protected page rendered while signed out looped (401 -> reset cache -> refetch -> 401): the reset now happens only on the first expiry; (5) `HydrateFallback` warning for lazy routes. My e2e script also had wrong waits and an edit that corrupted it once (rewritten).
- **Environment facts**: MUI 9 renamed icons (`ErrorOutlined`, `PersonOutlined`) and changed Autocomplete's `renderInput` params; use `http://localhost:5173` because the backend's CSRF origin allow-list names `localhost` (the backend correctly rejected `127.0.0.1`).
- **Known limits (documented in docs/FRONTEND.md)**: placeholders for the real screens; entry bundle ~511 kB (161 kB gzip); the e2e script is not part of `npm test` and Playwright is not a project dependency; not verified in Safari/Firefox, on a real phone, with a screen reader (only roles/labels asserted), or against `docker compose up`/MySQL 8.
- **Open questions**: should the cart icon also work for signed-out visitors (a client-side cart that merges at login) or is "sign in to shop" acceptable? Is the footer link set enough, or do you want placeholder help/legal pages?
