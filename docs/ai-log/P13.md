# P13: Search results and product page with offers table

## Prompt

TASK: Build /search?q= (results with "did you mean" behaviour when the top score is weak, and an empty state) and /product/:slug: gallery/cover, details, platform and region badges, and an offers table comparing sellers (price, region, seller rating, stock) with sorting, a "best price" highlight, and add-to-cart per offer.
CONSTRAINTS: Handle a product with a single offer and one with out-of-stock offers. Accessible table markup.
DONE WHEN: Adding two offers from different sellers works and the cart badge updates.

## Response summary

### Search (frontend/src/features/search, lib/didYouMean.ts)
- `/search?q=&page=` from `GET /api/search` (page and query in the address), reusing the store's grid and pagination. Out-of-stock matches show as "Out of stock".
- "Did you mean": on page 1, when the top score is below 0.75 (measured on the seeded catalog: strong matches 0.85-0.93, a one-letter typo 0.64) an alert suggests a corrected query. The API returns no suggestion, so `suggestQuery` repairs each word using the best match's title words (keeps words that are title words or prefixes of them; replaces others with the closest title word within ~1 edit per 3 letters; returns null when nothing would change). Without a usable suggestion it says "We found no close match. These are the closest games." Weak matches stay listed.
- Empty state (names the query, link to the store), no-query state (no request), page past the end, skeleton, error with retry.

### Product page (frontend/src/features/product)
- Cover (one generated cover per game exists, so no gallery; stated in the docs), name, platform/region/genre badges, publisher, release date, description, "From" price of the cheapest buyable offer.
- `OfferTable`: accessible markup (caption, `th scope="col"`, seller as `th scope="row"`, `aria-sort` on sortable headers, rating as `role="img"` with text, buttons named after the seller). Columns: seller, region, rating, stock, price (+crossed-out original), action. Sorting by seller/rating/stock/price (pure functions in `offers.ts`, stable tie-breaks, rating and stock biggest-first). "Best price" = cheapest buyable offer(s), text chip + border, only when >= 2 offers are buyable.
- Edge cases handled and tested: single offer (no highlight, explanatory note, still buyable); out-of-stock offer (greyed, disabled, never best, ignored by "From"); no buyable offers (message and link, no table); low stock warning; unknown slug; server error with retry.
- Add to cart: new `addToCart` mutation (POST /api/cart, invalidates the `Cart` tag, so the header badge refetches). Row shows "In your cart: n" from the server's cart; API errors show in the row. Signed-out visitors go to `/login?next=<product>` and back (the item is not auto-added after login: a deliberate simplification).
- Small shared pieces: `lib/visuallyHidden.ts` (HomePage's private copy moved there), `ProductGrid` reused from the store.

### Mistakes and fixes along the way
- First offers-table highlight put a yellow bar on two cells: `:first-of-type` matches the first `th` and the first `td`. `:first-child` then triggered an Emotion server-rendering warning (which the e2e console check caught); the final selector is `& > th`.
- `@mui/utils` is not a declared dependency; the table first imported `visuallyHidden` from it (lint did not object). Replaced by `lib/visuallyHidden.ts`.
- A test used `findByRole('status')` and could match the loading skeleton, passing or failing at random; the three-run flake was found by repeating the suite and the test now waits for the text.
- E2E script races again (checking `isVisible()` without waiting; reading the hint before the new answer arrived) fixed by waiting for the real condition. `shell.e2e.cjs` visited `/product/anything`, which is now a legitimate 404 with a console error; it visits a real product.

### Open points
- Cart page, checkout and orders screens are still placeholders; after signing in from the product page the item is not added automatically.
- "Did you mean" is a client-side heuristic over the best match's title; a server-side suggestion across all titles would be more reliable.
