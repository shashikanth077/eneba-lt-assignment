## Response summary

Premise corrections: the prompt assumed a schema and a `users` table already existed. They did not (P2 only documented the data model), so this task also created the SQL migrations and a small migration runner.

**Seed data**
- `backend/database/migrations/001-003*.sql` (users, login_attempts, platforms, regions, sellers, products, offers, deals, product_stats, game_keys, banners, home_blocks), `src/Support/Migrator.php`, `bin/migrate.php`.
- `backend/database/seeds/` (`Prng` xorshift32, `CatalogData`, `SvgArt`, `DatabaseSeeder`) and `bin/seed.php`, which runs migrations first and prints row counts: 6 platforms, 5 regions, 12 sellers, 120 products, 408 offers, 14,391 keys, 34 deals, 120 stats, 4 banners, 4 home blocks.
- Keys are `XXXXX-XXXXX-XXXXX`, encrypted with libsodium secretbox (`KeyCipher`) plus a sha256 fingerprint column for dedupe.
- Decisions: deals and product_stats are their own tables (own source per homepage block; replaces `offers.original_price_cents` from P2); covers and banners are generated SVGs stored in the DB and served by new `GET /api/images/...` endpoints so no file storage is needed.
- Verified: row counts, deterministic (identical content fingerprint after a full wipe and reseed), idempotent (a second run changes nothing; an already-sold key and changed stats survive a re-run), all 14,391 keys decrypt and match the format and hash, no plaintext in `key_enc`, all SVGs are valid XML, visual check of covers and a banner. Found and fixed an unrealistic deal (original price of 161 EUR) by capping crossed-out prices at 89.99.

**Authentication API**
- `POST /api/auth/register|login|logout`, `GET /api/auth/me`. Argon2id (`password_hash`, rehash on login), JWT via `firebase/php-jwt` in an `HttpOnly; SameSite=Lax; Secure` cookie (Secure configurable for local http), `AuthMiddleware` (cookie, signature, expiry, user exists, `token_version` match), `CsrfMiddleware` (required `X-Requested-With: fetch` + Origin allow-list), validation via the P4 `Validator`.
- Login never reveals whether an email exists: identical 401 body, dummy-hash verification for unknown emails, and a rate limiter (5 failures per IP+email, 20 per IP, 15 min window, `429` with `Retry-After`) that counts unknown emails the same way. Logout clears the cookie and bumps `token_version`, so the old JWT is dead server-side (trade-off: other devices are signed out too).
- Known trade-offs: register does return `409 email_taken` (standard UX trade-off, login does not leak); registration is not rate-limited yet.
- PHPUnit: 24 tests pass (12 auth integration tests against a real `keymart_test` database: register success + cookie flags + argon2id hash, duplicate email, validation, login success, wrong password vs unknown email byte-identical, rate limit, rate limit for unknown email, expired token, forged token, missing cookie, logout + revocation, CSRF; plus seeder/cipher tests). An existing test was updated because CSRF now runs before routing.
- README has a verified curl walkthrough (register, me, duplicate, wrong password vs unknown email, login, CSRF failure, logout, rate limit: `401 401 401 401 401 429`); it was also run for real against the local server.
- Dev setup: compose has dev-only `JWT_SECRET`/`KEY_ENCRYPTION_KEY` defaults and an init script creating the test database; `.env.example` files updated; ARCHITECTURE.md (API table, auth section, data model) and CLAUDE.md layout updated.
