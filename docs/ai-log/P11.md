## Response summary

### Homepage (frontend/src/features/home)
- `HomePage` fetches `/api/home/layout` (refetched on every visit) and `HomeBlocks` renders each block through `blockRegistry.ts`: `hero` -> `BannerCarousel`, `carousel` -> `ProductRail` (best sellers, deals and new releases are three rows using the same type; the endpoint and title come from the database).
- Every block fetches its own `endpoint` (RTK Query `getHomeBlock`), has its own skeleton, error state with retry, and its own error boundary (`BlockBoundary`). A failing request, a malformed payload or a render error affects only that block.
- Data from the database is treated as untrusted (`blocks.ts`): endpoints must look like `/api/<segments>`; malformed list items are dropped; unsafe banner `href`s are removed; unknown block types (including `constructor`) are skipped; empty blocks render nothing; "all blocks disabled" shows a message.
- No content is hardcoded: titles, banners, links, autoplay delay and limits all come from the API. Banner art no longer contains baked-in text (the seeder's `SvgArt::banner` draws only art; text is real HTML from the API).
- Shared: `ProductCard`, `QueryBoundary` now supports `loading`, `errorMinHeight` and `empty={null}`; `AppShell` `main` got `minWidth: 0` to stop wide grid children from stretching the page.
- Tests: 147 frontend tests (blocks parsing, reorder, disable, new block with existing type, unknown types, failing block + retry, malformed payload, invalid endpoint, skeletons, layout error/empty, revisit refetch, carousel and rail behaviour). Browser script `frontend/e2e/home.e2e.cjs` (20 checks) really edits `home_blocks`/`banners` through SQL, watches the page change without a frontend change, and restores the rows. The earlier shell script still passes (36 checks).

### XAMPP alignment (backend)
- PHP minimum lowered to 8.2 (XAMPP 8.2+); the lock file was refreshed.
- `LockStrategy` + `KeyRepository`: `FOR UPDATE SKIP LOCKED` only when the server has it (MySQL 8.0.1+, MariaDB 10.6+); otherwise plain `FOR UPDATE` (`LOCK_STRATEGY=auto|skip|wait`). `Transaction::runWithRetry` retries deadlock victims (max 3) in checkout, order lifecycle and the Stripe webhook; other errors are never retried.
- `APP_BASE_PATH` for Apache subfolder installs (`http://localhost/keymart/backend/public/api/...`) including the CSRF-exempt Stripe webhook path; `public/.htaccess` added.
- New tooling: `bin/setup.php` (create DB if missing -> migrate -> seed; `--no-seed`, `--test-db`), `--create-db` on `migrate.php`/`seed.php`, `bin/doctor.php` (PHP version, extensions, Argon2id, secrets, Stripe test key, cache, DB version, lock strategy, `max_allowed_packet`, `sql_mode`, pending migrations, demo data; exit 1 on blocking problems). `.env.xampp.example`, `.gitattributes` (LF for php/sql/sh), `docs/XAMPP.md`, README links.
- New backend tests: `LockStrategyTest`, `TransactionRetryTest`, `DoctorTest`, `DatabaseBootstrapTest`, `BasePathTest`. `ConcurrencyTest` interleaving tests that need SKIP LOCKED now skip themselves when the strategy is `wait`.
