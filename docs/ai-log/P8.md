# P8: Homepage blocks (layout + one endpoint, service class and cache per block)

## Prompt

CONTEXT: home_blocks, banners, deals, product_stats exist.
TASK: Implement GET /api/home/layout (ordered enabled blocks) and one endpoint plus one service class per block: /api/home/banners, /best-sellers, /deals, /new-releases. Each block owns its queries and caching (simple file/APCu TTL cache).
CONSTRAINTS: Blocks must not share code paths beyond a base interface, so each can later become its own service. Adding a new block type must not require frontend routing changes beyond registering a renderer.
DONE WHEN: Disabling a row in home_blocks removes that block from the API output, shown in a test.

## Response summary

- **Implemented**: `GET /api/home/layout` (enabled `home_blocks` rows by position as `{ id, type, title, endpoint, config }`) and one endpoint per block: `/banners`, `/best-sellers`, `/deals`, `/new-releases`. Each block is a `final` class implementing only `HomeBlock` (`slug()`, `path()`, `fetch(array $config)`), with its own SQL, card mapping, cache namespace and TTL (banners 5 min, best sellers 10, deals 2, new releases 10).
- **Done-when**: `HomeTest::testDisablingARowRemovesTheBlockFromTheApi` runs for each of the 4 blocks: disabling the row removes it from the layout, its endpoint answers 404, the other three stay 200, and re-enabling restores it.
- **Independence enforced by a test**: reflection + a scan of each file's `use` lines assert every block is final, extends nothing, uses no trait, takes only `(PDO, TtlCache)` and imports nothing but the interface, PDO and the cache interface. Deliberate cost: the three product-card blocks duplicate about 40 lines of SQL/mapping each, so any block can be extracted by copying one file plus its table.
- **Cache**: `TtlCache` interface with `FileTtlCache` (atomic write, best-effort: unwritable dir or corrupt file = a miss, never an error) and `NullTtlCache` (`CACHE_DRIVER=none`, used by tests); a `CacheFactory` gives each block its own folder under `CACHE_DIR`. APCu not implemented (not enabled in the CLI/Docker image; it would be one more class on the same interface). Cache keys include everything the output depends on (`limit`; the current day for new releases, since `CURDATE()` rolls over). The layout itself is not cached so disabling is instant. Measured: best-sellers 6.5 ms cold vs 3 ms cached.
- **Design decisions**: block routes are registered from class constants (`SLUG`/`PATH`) so building routes never opens a DB connection (otherwise `/health` could not report a DB outage); rows without a backend class are left out of the layout so the frontend never receives an endpoint that 404s; an empty config encodes as `{}`; `limit` is clamped 1-50; block endpoints list only buyable products and use the same cheapest-buyable-offer semantics as the catalog (deals: only products whose cheapest offer is on an unexpired deal).
- **API additions beyond ARCHITECTURE.md (docs updated, please review)**: layout items carry `config`; banners carry `ctaLabel`; deals items carry `originalPriceCents` (the card must show the crossed-out price; the catalog's ProductCard still has only `discountPct`); disabled blocks answer 404.
- **Frontend contract documented, not built**: layout once, then a renderer registry keyed by `type`, each renderer fetching its own `endpoint`; unknown type skipped. A new block with an existing `type` needs no frontend change; a new `type` needs one registered renderer and no routing change.
- **Tests**: 192 pass (was 158). New: `HomeTest` (18: layout shape/order/positions, the disable test x4, unknown-slug row, `{}` config, banners, best sellers incl. sold-out/inactive exclusion, limit clamping and junk config, deals incl. expired deal and deal-not-on-cheapest, new releases incl. future date, independence, slug/path consistency, TTL expiry with a fake clock and a statement-counting PDO, per-block TTL and isolation), `FileTtlCacheTest` (12), `HomeSeededTest` (4, on the real seed: row/endpoint consistency, content, ordering, banner images resolve). Mutation check, each caught: layout ignoring `enabled`, endpoint not 404ing when disabled, DealsBlock importing another block, BestSellers not caching, new releases including future dates (a first grep check of mine printed 0 and looked like a no-op; I re-ran it with a diff and confirmed it was applied and caught, plus 5 clean reruns for flakiness).
- **Mistakes found on the way (mine)**: a nonsensical expression I first wrote for the empty-config case (moved into the controller as a proper `stdClass`), key order of the layout JSON, and a test that tried to store non-JSON in a JSON column (impossible by design; replaced with valid-but-wrong JSON).
- **Not verified**: MySQL 8 (all on MariaDB 10.11); `docker compose up` (no daemon); the file cache on a read-only or multi-instance host beyond the unit tests; frontend not touched.
- **Open questions**: should `ProductCard` get `originalPriceCents` everywhere (catalog and search too) so every card can show the strike-through price? Do you want an APCu/Redis driver before deployment, or is per-instance file cache fine for the free tier?
