# P22: Vercel runtime errors (missing environment variables)

## Prompt

I found the errors in your Vercel runtime logs (Nov 10, 17:34). There are two problems, and both come from missing environment variables.

1. Database connection
/api/filters and /api/home/layout fail with SQLSTATE[HY000] [2002] Connection refused and return 503. Error 2002 means the app is trying to reach MySQL on 127.0.0.1 (localhost), where nothing is running. Your DB host variable is probably not set in Vercel, so the code falls back to localhost.

2. JWT secret
/api/auth/me fails with JWT_SECRET must be set and at least 32 characters long in TokenService.php:22 and returns 500.

## Response summary

Both errors are configuration, not code: `DB_*` and `JWT_SECRET` (and `KEY_ENCRYPTION_KEY`) are not set on the Vercel project, so the app used its defaults. I cannot set them (no Vercel access from this session); the user must add them in Vercel and redeploy. Code change: `ConfigGuard` now refuses to start on a public address when `JWT_SECRET` is missing/short or `KEY_ENCRYPTION_KEY` is empty, so a missing secret fails once, loudly, at start-up with a message naming the variable, instead of as a 500 on single endpoints. A PHPUnit test covers it. A missing `DB_HOST` still cannot be detected (it defaults to localhost); the log line `[db] connection problem` shows it.
