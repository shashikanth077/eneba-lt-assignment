# P9: Server-side cart, checkout with key reservation, Stripe webhook, orders

## Prompt

CONTEXT: Auth, offers and product_keys exist. Stripe test keys are in .env.
TASK: Implement cart endpoints (GET/POST/PATCH/DELETE /api/cart, server-side, auth required) and checkout: POST /api/checkout creates a pending order, reserves keys with SELECT ... FOR UPDATE SKIP LOCKED and a reserved_until timeout, creates a Stripe PaymentIntent (amount from the server, never the client), returns the client_secret. POST /api/webhooks/stripe verifies the signature and on payment_intent.succeeded marks the order paid and marks keys sold, idempotently. GET /api/orders and GET /api/orders/{id} return orders, with decrypted keys only for paid orders owned by the caller.
CONSTRAINTS: Prices recomputed server-side. Handle out-of-stock mid-checkout, expired reservations, webhook retries, and failed payments. Write tests for the concurrency case where two buyers compete for the last key.
DONE WHEN: Stripe CLI `stripe trigger payment_intent.succeeded` (or a real test card flow) results in a paid order with keys visible only to its owner.
