## Response summary

Analysis found the database layer already generic (one PDO class, env-only settings, errors hidden from responses), the schema fully reconstructable from migrations 001-007 (nothing missing), no admin area and no categories table. Changes: `config/settings.php` accepts `MYSQL_*` as aliases of `DB_*` (DB_* wins), and no longer defaults to localhost outside `APP_ENV=local|test`; `ConfigGuard` refuses to start without a DB host in a deployment. New `backend/database/railway_import.sql` (schema = the 7 migrations verbatim, migration ledger, seeder reference data and 2 demo users, no DROP). Game keys are excluded on purpose (encrypted with the owner's key; created by `php bin/seed.php` after import). New `docs/RAILWAY.md` (analysis, variable table, Railway steps, Vercel variables, runtime check, verification split tested/untested); `.env.example`, DEPLOY.md pointer, CI step that loads the file into MySQL 8.

Verified locally (MariaDB standing in for XAMPP): import OK, second import refused, app runs with only MYSQL_* variables, seeder adds ~14k keys and leaves imported rows, API smoke (health, list, detail, filters, typo search, home, demo login, register, me), full PHPUnit 365 tests. A bug in my new settings test (it wiped `$_ENV` for later test classes and silently skipped 149 DB tests) was found and fixed before committing.

Not tested (needs credentials): Railway TCP proxy, importing to Railway, Vercel redeploy. Vercel has no PHP runtime; the repo relies on the container service, unproven; fallback options are in RAILWAY.md. Admin features: none exist.
