# P15: Hostile review, REVIEW.md, and the top five fixes

## Prompt

TASK: Act as a hostile senior reviewer. Review the whole repo for: security (auth, injection, IDOR on orders, webhook verification, key exposure, CORS), concurrency in key allocation, accessibility, and performance. Produce docs/REVIEW.md ranking findings by severity, then fix the top five and explain each fix.
DONE WHEN: Each fix has a test or a reproducible check.

## Response summary

### How the review was done
Read the security-relevant code end to end (middleware, auth, throttling, orders/keys, webhook, payment lifecycle, SQL builders, config), then attacked the running app: curl with spoofed headers, 16 parallel OS processes against the login limiter, headless Chromium with axe-core (WCAG 2.0-2.2 A/AA) over every page including signed-in ones, `npm audit` / `composer audit`, and a contrast calculation of the design tokens. `docs/REVIEW.md` lists 19 findings ranked by severity (5 fixed, 14 open with the intended fix) plus what I tried to break and could not (webhook, orders IDOR, key allocation races, SQL injection, CSRF/CORS, XSS, dependencies). Findings that come from reading code only are labelled as such.

### The top five and their fixes (each with tests and a reproducible check)
1. **S1 High: `X-Forwarded-For` trusted by its first (client-controlled) entry.** Twelve wrong passwords with a fresh fake first entry each all got `401`; the limiter never fired. `ClientIp` now takes the entry N places from the right (`TRUSTED_PROXY_HOPS`). `ClientIpTest`, `ProxyThrottleTest`; verified again by hand against the fixed server (`401 x5`, then `429`).
2. **S2 High: published placeholder secrets accepted on a public deployment** (forge sessions, decrypt keys). New `ConfigGuard` makes the app refuse to start when the deployment is not local (APP_ENV local/test *and* loopback APP_URL) and uses the placeholder JWT secret / key-encryption key, insecure cookies or debug. Doctor reports it. `ConfigGuardTest` (12 cases incl. the copied-`.env.example` scenario and the real bootstrap refusing).
3. **S3 High: no limits on registration (Argon2id), checkout (15-minute stock lock), search (catalogue scan).** New database-backed `RateLimiter` + middleware + migration 006: 10 registrations/hour/IP, 10 checkouts/10 min/account, 240 searches/min/IP, configurable; `429 rate_limited` with `Retry-After`; the SPA message handles it. `RateLimitTest` incl. a two-connection burst.
4. **S4 High: login limiter was check-then-record**; 16 parallel guesses all reached the password check. `claimAttempt` now records first and counts after, which bounds the number of requests that can pass by the limit (argument in the code comment). `LoginRaceTest` spawns 16 real processes (<= 5 pass).
5. **S5 Medium: private responses had no `Cache-Control`**, including the paid-order response with plain-text keys. `SecurityHeadersMiddleware` (outermost): `no-store` unless the handler chose caching, nosniff, DENY, no-referrer, HSTS on HTTPS. `SecurityHeadersTest` checks a paid-order response that really contains keys.

Every fix was checked by mutation (put the vulnerable behaviour back, a test fails, restore): spoofed first entry, guard call removed, register unlimited, checkout limited per address, headers middleware removed, check-then-record. Final runs: backend 347 tests, frontend 291, lint/typecheck clean.

### Findings I ranked but did not fix (details and fixes in REVIEW.md)
EmailJS abuse by anyone holding the public key (High), distributed guessing, lazy release of abandoned reservations, stock hoarding with many accounts, four serious accessibility issues found by axe (no route titles/focus management, 10 px carousel targets and no pause, label-in-name mismatches, yellow in-text links at 1.45:1 and 3.9:1 placeholders), search scan cost, cart COUNT queries, bundle/font, missing SPA hosting headers, accepted e-mail enumeration, refund reconciliation.

### Mistakes and fixes along the way
- My first S1 repro did nothing: `TRUST_PROXY` in `backend/.env` overrode the variable I passed (Dotenv fills `$_ENV` first). Reproduced properly by editing the (git-ignored) `.env`, then restored it.
- Slim cannot bind a static closure used as middleware (it passed `null`): replaced by a middleware class with a lazy limiter factory; also fixed closures missing `use` variables. The first version also built the limiter, and so the database connection, while registering routes.
- The new registration limit stopped my own accessibility script and would stop repeated browser e2e runs (10/hour from one address): documented `RATE_LIMITS_ENABLED=false` in `.env.example` and the e2e script headers.
- I first numbered the login race S5 and the caching issue S4, then re-ranked (race above caching) and renamed the references in tests and code comments.
- Two of my own new tests were risky/failing on first run (`expectNotToPerformAssertions` with assertions; a registration collision between runs); fixed.

### Limits of this review
No real Stripe, EmailJS or production host; one-box load only (no load test); accessibility was tested with an automated checker (axe finds roughly a third of WCAG issues) and no screen reader.
