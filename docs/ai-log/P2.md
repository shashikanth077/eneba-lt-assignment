## Response summary

- Created `docs/ARCHITECTURE.md` covering scope table, Mermaid system diagram + payment sequence diagram, full REST API table, auth, payment/key allocation, homepage blocks, fuzzy search, data model summary, top 5 risks, and 8 assumption questions.
- Kept all stated decisions, but flagged **CHALLENGE** points:
  - JWT is not revocable: added `users.token_version`; CSRF via SameSite=Lax + custom header + Origin check.
  - Vercel rewrite adds a hop and cold-start exposure; Stripe webhook must bypass it (raw body, no cookie).

  - `LIKE` alone cannot find typos: candidate generation uses LIKE on query trigrams (cap 200), then PHP trigram Jaccard + Levenshtein re-rank; documented ceiling (~10k rows).
  - EmailJS is client-side/public: welcome and key-less receipt only.
  - "Separate services" for homepage blocks implemented as separate modules/endpoints/tables, with layout stored in DB; no separate deployables.
- Top risks: free hosting fit (no free MySQL on Render, cold starts), payment/key races, styling time sink (design reference missing), search quality/perf, security slips.
