## Prompt

[Screenshot: the payment result page showing only a spinner and "Confirming your payment…"]

after successfull payment its not giving any success message and still in same page and also not getting any email after order confirmation,

update the readme file up to date

## Response summary

**Cause.** An order only becomes paid when Stripe's webhook has been processed, and the payment page only waits for that. On the deployed site the webhook evidently did not reach/verify (wrong address, no signing secret, or secret of another endpoint), so the order stayed pending and the page kept polling. The confirmation e-mail is sent by the browser when the order turns paid, so it never went out either. One cause, two symptoms. I cannot see the deployed Stripe or API logs, so which webhook setting is wrong is not confirmed.

**Fix (backend).** When the payment page (or order page) asks for a **pending** order, the server now asks Stripe itself (`PaymentGateway::retrieveIntent`, server to server, secret key) and, if the payment `succeeded`, fulfils the order through the same `PaymentEventService` routine as the webhook: amount/currency checked, already-paid is a no-op, a webhook arriving later changes nothing, a Stripe outage is logged and retried on the next poll, and a stranger asking cannot trigger anything (404). So the buyer reaches the order page with the keys and the e-mail trigger fires even with no working webhook. 6 new PHPUnit tests; suite 393.

**Fix (frontend).** The confirmation e-mail is now `spawn`ed: the payment page navigates away the moment the order is paid, which cancels the polling saga, and the e-mail must not be cancelled with it.

**Not verifiable from here / needs the user.** Whether the e-mail arrives still needs `VITE_EMAILJS_SERVICE_ID/PUBLIC_KEY/ORDER_TEMPLATE_ID` set where the frontend is built (Vercel) and the order template saved in EmailJS; and `STRIPE_SECRET_KEY` must be set on the API (the new confirmation needs it). The webhook should still be fixed (docs/DEPLOY.md). Troubleshooting rows added.

**README** rewritten to the current state: features, documentation map, layout, local run (Docker, XAMPP), demo accounts, payments/e-mail settings, how a payment is confirmed, configuration, game keys and seeding, deployment, checks and CI, API quick reference, troubleshooting. docs/CHECKOUT.md and docs/DEPLOY.md updated.
