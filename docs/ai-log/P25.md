# P25: List all products regardless of stock

## Prompt

Because the API's initial product fetch uses the same "in-stock only" query as the shop listing.
Although products are stored, the repository joins them with offers containing at least one available game key. Since there are zero available keys, the initial fetch returns no products.
So currently:

* Product data exists.
* Offers exist.
* Inventory keys do not exist.
* `/api/products` hides products without inventory.

If the homepage should display the catalog before inventory exists, the listing query must be changed to show products independently of stock.

need to resole this to fetch all the products initial

## Response summary

`ProductRepository::BASE_FROM` now always uses a LEFT JOIN to the cheapest in-stock offer (it was INNER for browsing, LEFT only for search). Products without a buyable offer are listed with `inStock:false`, `fromPriceCents:null`, no price, and last when sorting by price; filter facets and the total count them too (the price range still reflects buyable offers only). The frontend card already renders "Out of stock". Verified on a database imported from `railway_import.sql` with zero keys: `/api/products` total 120, `/api/filters` 6 platforms / 5 regions / 10 genres. 19 existing tests encoded the old rule (sold-out/inactive products hidden) and were updated deliberately to the new contract; PHPUnit 366 passing. Not changed on purpose: homepage rails Deals / Best sellers / New releases still need buyable offers (they remain empty until keys exist; `SEED_ON_START=if-empty` creates them, P24). Open question: if you want those rails to show unbuyable products too, say so.
