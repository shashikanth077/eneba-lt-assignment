# P12: Store page (filters, sort, grid, URL state)

## Prompt

TASK: Build /store: filter sidebar (platform, region, price range slider, genre) that collapses into a drawer on mobile, sort dropdown, product grid with pagination or infinite scroll, active-filter chips, and a search box. Keep all filter and sort state in the URL query string so pages are shareable and back/forward works.
CONSTRAINTS: Debounce price changes, use RTK Query caching, product card matches DESIGN_TOKENS.md.
DONE WHEN: Reloading a filtered URL reproduces the exact same view.

## Response summary

### What was built (frontend/src/features/store, plus ProductCard)
- **URL is the only state.** `storeQuery.ts` parses the address into a view (`q`, repeated `platform`/`region`/`genre`, `price_min`/`price_max` in cents, `sort`, `page`), writes the canonical address back (defaults omitted, lists sorted) and builds the API query strings. Invalid or stale addresses are repaired instead of failing (page -3, unknown sort, `sort=relevance` without a search text, min > max, over-long search). `useStoreQuery` updates the address with a functional `setSearchParams`; any change except the page resets to page 1; on the default sort the default follows the search text.
- **UI:** `FilterSidebar` (platform/region/genre checkboxes with counts, price range slider), `PriceFilter`, `StoreSearch` + `SortSelect` + `FiltersButton`, `ActiveFilters` (a chip per filter with an x, plus Clear all), `ProductGrid` + skeleton, MUI `Pagination`. Below `lg` the same sidebar is rendered inside a `Drawer` (button with active-count badge; changes apply live; "Show N games" closes it).
- **Debounce:** slider and search box keep local drafts and write the address 400 ms after they rest; they follow the address when it changes by other means (Back, chip, Clear all).
- **RTK Query caching:** products and filters take the query string as the argument, so revisiting a view within 60 s makes no request. The two filters endpoints were merged into one (`catalogApi.getFilters(queryString)`), so the navigation bar and the store share the unfiltered call, which also supplies the catalog-wide price bounds (the slider range must not shrink while filtering).
- **History decision:** discrete changes push history entries (Back undoes them); search typing replaces the entry.
- **ProductCard** reworked to DESIGN_TOKENS.md section 6 (267x337 cover, 27 px platform strip, single-line 14/700 title, region label, "From" row with green discount, 22/800 price). Cashback badge/line deliberately not built (no cashback in this shop). Home tests adjusted for the region label no longer repeating the platform.
- **Pagination vs infinite scroll:** pagination chosen because the page number can live in the URL and be reproduced exactly.

### Verification

### Mistakes and fixes along the way
- A real bug found by a test: typing a search left `sort=popular` in the address (default sort follows the search text now).
- Two facet requests for the same unfiltered URL (navigation bar vs store used different cache keys): one endpoint now.
- Lint rejected setState-in-effect for syncing drafts with the address: replaced with state derived during render.
- First phone-drawer screenshot looked broken: it was taken mid slide-in animation; the script waits now.
- Several e2e failures were races in my script (reading the grid before the new answer arrived), fixed by waiting on the actual response, not by loosening checks.
